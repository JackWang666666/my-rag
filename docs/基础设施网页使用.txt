基础设施网页端使用说明
======================

本项目用 docker compose 起了 5 个基础设施容器：etcd、MinIO、Milvus、Neo4j、Attu。
其中 etcd 和 Milvus 本身没有网页界面；日常需要在浏览器里点来点去的，是下面三个：

  1. Neo4j Browser  —— 图数据库（存知识图谱：实体和关系）
  2. Attu           —— Milvus 的管理界面（存向量数据，用于语义检索）
  3. MinIO 控制台    —— Milvus 底层用的对象存储，一般不需要手动管它

前提：先执行过
  cd docker
  docker compose up -d
容器都 healthy 之后再打开下面的网址。


一、Neo4j Browser（图数据库）
----------------------------

地址：http://localhost:7474

登录：
  用户名：neo4j
  密码：  neo4j123456
  （这两个值在 docker/.env 里对应 NEO4J_USER / NEO4J_PASSWORD，没改过就是默认值）

打开后分两块：
  左边：Database Information 侧栏，显示当前库里有哪些节点标签（Node labels）、
        关系类型（Relationship types）、属性字段（Property keys）。
  上面：一个输入框，可以敲查询语句（叫 Cypher，类似 SQL）。

常用操作：

  1. 看看库里有多少数据（最常用，确认写入是否成功）
     在输入框敲：
       MATCH (n) RETURN count(n)
     回车，会告诉你节点总数。

  2. 随便看一批节点，画成图
       MATCH (n) RETURN n LIMIT 25
     执行后下面会出现一张"小圆点连线"的图，圆点是节点，线是关系。
     鼠标点一个圆点可以展开看它周围连了哪些东西，拖动可以调整位置。

  3. 看节点和它的关系一起
       MATCH (a)-[r]->(b) RETURN a, r, b LIMIT 25

  4. 按名字查某个实体
       MATCH (n) WHERE n.name = "你要找的名字" RETURN n

  5. 删掉所有数据（慎用，整个库清空）
       MATCH (n) DETACH DELETE n

  左侧栏里以 : 开头的不是 Cypher，是浏览器自带命令，比较有用的：
    :schema         看数据库结构概览
    :server status  看当前连接状态
    :history        看历史执行过的查询

出结果后，右上角有几个小图标：
  图钉：把这条结果固定住，不会被你下一条查询顶掉
  双向箭头：全屏看
  上箭头：收起结果，只留查询框


二、Attu（Milvus 管理界面）
---------------------------

地址：http://localhost:3300

打开后让你填连接地址，填：
  milvus:19530
（注意：是容器内部地址，不是 localhost，因为 Attu 本身也跑在容器网络里）

打开后左边能看到所有的 Collection（可以理解成"表"，这里存的是文档切片之后
生成的向量，每个知识库通常对应一个或几个 Collection）。

常用操作：

  1. 看有哪些 Collection、各有多少条数据
     点左侧 Collections 列表，右边会显示每个 Collection 的行数（Row Count）。
     行数应该随着你在前端上传文档增多而增多，用来确认"文档有没有真的被
     处理并写进向量库"。

  2. 看某个 Collection 的字段结构
     点进某个 Collection，有 Schema 标签页，能看到字段名（比如 id、
     content、embedding 向量字段）。

  3. 简单查询 / 搜索
     进入 Collection 后有 Data 或 Query 标签页，可以按条件查某几条数据，
     不需要手写代码。

  4. 删除某个 Collection（慎用，对应知识库的向量数据会全部丢）
     列表里选中后用删除按钮。正常应该通过前端删除知识库，不建议直接在
     这里删，容易和 SQLite 里的元数据不一致。

Attu 主要是用来"确认数据有没有写进去、数量对不对"，日常排查问题用，不建议
在这里直接改数据。


三、MinIO 控制台（一般不需要用）
--------------------------------

地址：http://localhost:9001

登录：
  用户名：minioadmin
  密码：  minioadmin

这个是 Milvus 内部用来存向量索引文件的对象存储，相当于 Milvus 的"硬盘"。
正常情况下你不需要进这个界面操作什么，Milvus 会自己管理里面的内容。
只有在怀疑 Milvus 存储层出问题（比如磁盘占用异常、容器一直重启）时，才
进去看一下 bucket 里的文件占用情况，日常使用可以完全忽略这一部分。


四、排查思路小结
----------------

前端上传文档后，如果想确认数据是不是真的处理成功了，可以按下面顺序查：

  1. 先看 Milvus（Attu）：对应 Collection 的 Row Count 有没有增加
     → 没增加说明向量化这一步没跑成功，去看后端日志。

  2. 再看 Neo4j：MATCH (n) RETURN count(n) 节点数有没有增加
     → 没增加说明知识图谱抽取这一步没跑成功，也去看后端日志
       （不是所有项目配置都开启了图谱抽取，要先确认这一步是不是必选项）。

  3. 两边都有数据，但前端查询结果不对 → 问题大概率在后端的检索/排序逻辑，
     不是基础设施层的问题，这两个网页界面帮不上忙了。
